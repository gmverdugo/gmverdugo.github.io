# Portfolio v2

Personal portfolio of Gonzalo Verdugo, Enterprise Observability Architect. A single-page, chapter-based dossier in two languages: English at `/` and Spanish at `/es/`. It is a fully static site. It ships no client-side JavaScript except for the Fig. 1 player (see "Fig. 1, live composition").

## Stack

- Astro 7, static output, TypeScript strict
- Tailwind CSS 4 through `@tailwindcss/vite`, tokens declared in `src/styles/global.css`
- Astro Fonts API with Fontsource (Newsreader, Inter, JetBrains Mono), self-hosted at build time
- `@astrojs/sitemap` for `sitemap-index.xml`, with `hreflang` alternates
- Astro built-in Content Security Policy (meta tag with hashes for the inline styles and scripts)
- `@hyperframes/player` (the `<hyperframes-player>` web component) for the live Fig. 1 animation, loaded lazily

## Commands

Run from this directory. Node 22 is required (see `.nvmrc`).

| Command                | Action                                   |
| ---------------------- | ---------------------------------------- |
| `npm install`          | Install dependencies                     |
| `npm run dev`          | Dev server at `http://localhost:4321`    |
| `npm run build`        | Static build into `dist/`                |
| `npm run preview`      | Serve the production build locally       |
| `npm run check`        | Type and template check (`astro check`)  |
| `npm run format`       | Format everything with Prettier          |
| `npm run format:check` | Verify formatting without writing        |
| `npm run fig1:sync`    | Rebuild `public/fig1/` from compositions |

The Content Security Policy is not applied by the dev server. Test it with `npm run build` followed by `npm run preview`.

## Content and i18n workflow

All copy lives in typed files under `src/i18n/sections/`. Each file exports a `Localized<T>` value, that is, an object with an `en` and an `es` entry of the same type.

1. To add or change copy, edit `src/i18n/sections/<section>.ts` and provide the text for both `en` and `es`.
2. `Localized<T>` makes `npm run check` fail when a key is missing in either language.
3. `src/data/chapters.ts` is the id registry. Chapter anchors, the header navigation and section ids derive from it, so add a new chapter there first.
4. Facts in `src/data/site.ts` and in the section files must come from verified sources. Do not invent figures.
5. Language switching is a plain link between `/` and `/es/`, not a script.

## Design rules

- Hex colors exist only in `src/styles/global.css` (the single exception is the `theme-color` meta tag in `Base.astro`, which cannot read CSS tokens). Components use the token utilities (`bg-canvas`, `text-ink`, `border-rule`, ...).
- Zero client JavaScript, with one documented exception: the Fig. 1 player (lazy module plus a small observer script in `FigPlayer.astro`). Everything else is plain HTML and CSS.
- CSS animations are finite and are disabled under `prefers-reduced-motion`. The Fig. 1 animation loops, so it has a Pause/Play button and does not autoplay under `prefers-reduced-motion`.
- No shadows, no gradient text, no corner radius above 12px, no emojis.
- Keep the semantic structure: one `h1`, ordered headings, a skip link, visible focus states.

## Fig. 1, live composition

Fig. 1 of the Architecture chapter is a 30-second HTML/GSAP composition (HyperFrames) played live by `<hyperframes-player>` from `@hyperframes/player`. It is not a video file. It follows one illustrative event through the five stages and then zooms out to the whole pipeline. Component: `src/components/diagram/FigPlayer.astro`. Copy: the `player` block of `src/i18n/sections/architecture.ts`.

### Files

`public/fig1/` is generated, do not edit it by hand:

| File                                       | Use                                                |
| ------------------------------------------ | -------------------------------------------------- |
| `landscape-{en,es}.html` (1600x900)        | Viewports of 768px and wider                       |
| `portrait-{en,es}.html` (1080x1350)        | Viewports below 768px (max 480px wide)             |
| `poster-{landscape,portrait}-{en,es}.webp` | Poster shown before the first frame                |
| `assets/`                                  | Fonts, `gsap.min.js`, `hyperframe.runtime.iife.js` |

### Runtime contract (found by experiment, player and core 0.8.158)

- When a composition has no HyperFrames runtime, the player injects a `<script src>` pointing to `https://cdn.jsdelivr.net/npm/@hyperframes/core@<version>/dist/hyperframe.runtime.iife.js`. We do not allow that: no CDN, no external origin (CSP and privacy).
- The prebuilt runtime is `@hyperframes/core/runtime` (`dist/hyperframe.runtime.iife.js`, about 510 KB, 160 KB gzip). `npm run fig1:sync` copies it to `public/fig1/assets/` and injects `<script data-hf-runtime src="assets/hyperframe.runtime.iife.js">` right after `<head>` in every composition. When the runtime is already there the player injects nothing, so no request leaves the origin.
- Compositions are loaded through the `src` attribute as same-origin URLs (never `srcdoc`), so the page CSP is not inherited by the iframe and the composition keeps its inline script and styles. The CSP only needs `frame-src 'self'` on top of the existing `default-src 'self'`.
- The player attribute `runtime-src` (same-origin or localhost only) is an alternative to injecting the script into the files. It is not used.
- Do not set `sandbox-origin` on the player: the iframe gets an opaque origin and its fonts are blocked by CORS (verified in preview).
- Known and unavoidable: the player creates the iframe with `sandbox="allow-scripts allow-same-origin"`, and Chrome logs a console warning ("can escape its sandboxing"). The content is first-party, so the risk does not apply. Lighthouse is not affected (Best Practices 100).

### Refresh after regenerating the compositions

1. Render the four compositions, four posters and `assets/` into one folder (default `../Video-Fig1/fig1-journey/out/web`, with the file names above).
2. Run `npm run fig1:sync` (or `npm run fig1:sync -- path/to/folder`). It wipes and rebuilds `public/fig1/`, copies the runtime and injects it once (idempotent).
3. Update `player.steps` in both languages if the captions changed (keep them identical to the animation).
4. Run `npm run build` and test with `npm run preview`.

To upgrade the player, change the exact version of `@hyperframes/player` and `@hyperframes/core` together (they must match) and run `npm run fig1:sync` again.

### Behavior

- Only one composition is used: the script removes the non-matching `<hyperframes-player>` before the player module loads, so a single iframe is ever created.
- Lazy: the player module and the composition are not requested until the figure is within about one viewport of the screen (`IntersectionObserver`, `rootMargin: 100% 0px`). `autoplay muted loop low-power-idle`. It pauses when the figure leaves the viewport or the tab is hidden, and resumes when it returns.
- Size is fixed by CSS (`aspect-ratio`), so there is no layout shift.
- JS cost (gzip): component script 1.4 KB, player chunk 29.9 KB (lazy). The iframe then loads the runtime (about 164 KB gzip) and GSAP (28 KB gzip) from `public/fig1/assets/`.

### Accessibility

- `prefers-reduced-motion: reduce`: no autoplay and no composition request. The poster is shown until the visitor presses Play.
- A labelled Pause/Play button (EN/ES, keyboard focusable, 36px high) calls `pause()` and `play()` on the player (WCAG 2.2.2). The animation loops, and the visitor controls it.
- Text alternative: the player has `role="img"` and an accessible name. The `<figcaption>`, the glossary, a `<details>` with the six steps ("Read the steps as text") and `StageList` (the five stages and their modules, screen-reader only on screen, visible in print) describe the content.
- Print: the animation is hidden, the stage list is shown.

## Portrait

An optional portrait is picked up automatically when a file named `profile.jpg`, `profile.jpeg`, `profile.png` or `profile.webp` exists in `src/assets/`. Without it the cover renders no image.

## Build output and deployment

- `npm run build` writes a static site to `dist/`: `index.html`, `es/index.html`, `404.html`, `sitemap-index.xml`, `robots.txt` and hashed assets under `_astro/`.
- Site URL: `https://gmverdugo.github.io`, with `base` set to `/` (a user site, not a project site).
- Deployment target is GitHub Pages with the Pages source set to GitHub Actions. The workflow must run `npm ci` and `npm run build`, then publish `dist/`.
- `public/.nojekyll` is included so GitHub Pages serves the `_astro/` directory untouched.
- Open Graph images are static files (`public/og-en.png`, `public/og-es.png`, 1200 x 630). Regenerate them if the name or job title changes.
